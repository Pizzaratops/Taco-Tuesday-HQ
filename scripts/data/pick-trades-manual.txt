# ============================================================
#  PICK-TRADE-JOURNAL — nur fuer Picks, die ESPN NIE sieht
# ============================================================
#  ESPN modelliert immer nur den unmittelbar bevorstehenden Draft
#  (aktuell TTHQ-Jahr 2026, automatisch abgeglichen von
#  scripts/sync-espn-picks.js). Ein Trade, der einen Pick fuer den
#  Draft DANACH bewegt (TTHQ-Jahr 2027 und spaeter), taucht bei ESPN
#  in keiner API auf -- dafuer ist diese Datei da.
#
#  EINE ZEILE PRO GEHANDELTEM PICK. Format, mit Komma getrennt:
#    datum, jahr, runde, originalOwner, neuerBesitzer, notiz
#
#  - datum:        wann eingetragen (nur zur Nachvollziehbarkeit)
#  - jahr:         TTHQ-Jahr des Drafts (2027, 2028, 2029 ...)
#  - runde:        1-4
#  - originalOwner: TT-Team-ID, der das (year,round,originalOwner)-Tripel
#                   in data/picks.js bereits zugeordnet ist -- NICHT wer
#                   den Pick gerade abgibt. Im Zweifel im Admin unter
#                   "Pick uebertragen" nachsehen, welches Tripel gemeint ist.
#  - neuerBesitzer: TT-Team-ID, die den Pick jetzt haelt
#  - notiz:         frei, taucht im Diff/Log auf
#
#  Anwenden: node scripts/apply-pick-journal.js
#  Laeuft NICHT automatisch taeglich (anders als der ESPN-Pick-Sync),
#  weil hier ein Mensch den Trade erst eintragen muss -- das Script
#  wendet nur an, was hier steht. Am einfachsten nach jeder neuen Zeile
#  einmal von Hand laufen lassen, oder ueber GitHub Actions "Run workflow"
#  (falls als eigener Schritt eingerichtet).
#
#  Team-IDs siehe data/teams-rosters.js (TEAMS-Array).
# ============================================================
